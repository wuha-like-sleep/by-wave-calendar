# 服务端 1.7.0

> 取代 1.6.16。这一版动得比较多，**先看第一节**，只有一种部署形态需要你动手。

---

## 一、升级前：只有一种情况要先改一行

**nginx 和日历程序装在同一台机器上**（宝塔的标准装法）—— 什么都不用改，直接升。

**nginx 装在另一台机器 / 另一个容器里，或者前面还套了 CDN** —— 升级前先在 `.env` 里加一行：

```
TRUST_PROXY=<那台反向代理的地址或网段>
```

不加会怎样：**所有访客会被算成同一个人**共用访问频率额度，访问量不大就开始随机拒绝请求，而且后台看不出来。`.env.example` 里有完整说明。

（原因：以前「访客的来访地址」取自调用方自己写的请求头 —— 换一个伪造值就能绕开所有访问频率限制，审计日志里记的也是对方填的字符串。现在按可信的那一跳取，代价是分离部署的站点要告诉程序哪一跳可信。）

---

## 二、最要紧的一条：在手机上编辑事件不再丢东西

以前在 iPhone 或安卓上编辑任何一个事件（哪怕只是拖一下时间），**网页上设的提醒、参与者、分类会一起消失**。两端都显示保存成功，不报任何错。

根因是事件的附加信息以前是整块替换，而手机端的模型里根本没有「提醒」这个字段。现在改成逐字段合并。

**这条不用等 App 发版** —— 服务端传上去，用户手上已经装着的那些版本立刻不再丢数据。

---

## 三、建号的口子

**`/api/auth/register` 是一个完全不设防的注册接口**：不看注册策略、不要邀请码、没有验证码、不验邮箱、建完直接给会话，而且**一条审计记录都不留**。网页的注册表单走的是另一条有闸门的路，三端 App 从来没调过它 —— 也就是说它没有任何正经用途。

往下查发现建号一共有五个入口，**只有网页注册表单那一个看后台的「注册策略」开关**。你把注册设成「关闭」或「邀请制」，另外四条路照样建号。审计里那些不认识的账号来自其中一条：外部平台的服务客户端自动开通。

现在所有入口走同一道闸门，统一判注册策略、邮箱域名白名单、每日名额；每个账号记下自己是怎么来的，后台能按来源筛、能批量停用。

顺带堵了两条账号接管：

- 用 SSO 登录时拿对方给的邮箱去认领已有账号，**从不检查那个邮箱验没验过** —— 接一个允许自填邮箱的登录源，别人注册你的管理员邮箱就能登进你的号。
- 先用别人的邮箱抢注一个没验证的号，等本人用苹果或 SSO 登录时把他并进来，而抢注者的密码一直有效。

## 四、出错时不再把服务器内部的东西送出去

出错响应里带不带服务端的报错原文，以前是按环境变量分档的：生产不带、开发照常带。听起来合理，但**那个变量的默认值是「开发」** —— 你起服务时不专门设它，跑的就是「照常带」那一档。带出去的是数据库报错原文：**内网地址和端口、服务器上的绝对路径、SQL 语句**。一条 500 就够送一次。

现在无条件不外送，细节只进日志。

---

## 五、提醒

- **发信失败不再被记成「已发送」。** 以前发信函数从不抛异常、失败时只是返回一个「没成功」，而扫描器不看这个返回值，直接记进已发表。结果是 SMTP 一出问题，那批提醒既没发出去、也**永远不会重试**，日志还在打印「已发送 N 条」。
- **全天事件的提醒时刻修正了**（见下一节，这条用户会感觉到）。
- **共享日历的成员也能收到提醒了。** 以前只有日历的所有者收得到。
- **在 iPhone 自带日历里删掉提醒，服务端不再按老提醒继续发。** 以前删不掉。
- 「提前一周」「准时」「事件结束前」这些写法不再被静默丢弃 —— 以前写进去接口返回成功、事件详情里看得见，但到点永远不响。
- 参与者以前在网页和 CalDAV 之间是两种不兼容的形状，后果是：手机上加的人在网页保存一次就没、网页加的人在 iPhone 上根本不显示、点「移除」怎么点都删不掉、再点「邀请」还会**重复发一封邀请邮件**。现在收口成一种。

---

## 六、用户会感觉到的变化（建议写进你给用户的通知）

**1. 全天事件的提醒时刻变了。**
以前全天事件套用「提前 N 分钟」算不出合理的时刻。升级时会自动把已有的档位换成「当天 09:00 / 前一天 09:00 / 一周前 09:00」里最接近的一档。只改还没发生的事件，历史事件不动，也不会因为换档重复提醒。

**2. 共享日历的成员会开始收到提醒邮件。**
一个共享给 50 个人的日历，事件到点会给 50 个人各发一封。以前只有所有者收得到 —— 这是补齐，但量会明显变大，提前知道一下。

**3. 手机和电脑上的日历客户端会重新同步一次。** 属于正常现象。少数人可能要在客户端里手动下拉刷新一次，提醒才会出现。

**4. 用手机日历删某个事件的提醒时，个别第三方客户端可能删不掉** —— 请改在网页上删。（新口径要求客户端带上版本标识才认删除，主流客户端都带。）

## 七、后台新增

**设置 → 设备同步**：可以手动让所有已连接的日历客户端重新同步一次（以前只有发版时自动触发一次）。走两步确认，带审计记录。

## 部署

把 `by-wave-calendar-v1.7.0.tar.gz` 和 `.sig` 一起传到后台「系统更新」。
数据库迁移随启动自动应用。`.env` 除了第一节那种情况之外不用改。

### 传完验一下

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://rl.lz-ss.com/health
```

返回 **200** = 起来了。

⚠️ 这一版顺带修了一个**会让服务起不来**的问题：启动顺序以前是「先读配置表、
后跑数据库迁移」，而这一版给配置表加了列 —— 用新代码去读还没迁移的老库会直接
报「列不存在」然后退出，表现是 pm2 反复重启。所以这一版**必须整包升级**，
不要只替换部分文件。

再看两处，都是这一版新加的，看得见就说明升对了：

- 后台 **用户** 页，列表里多了一列**来源**。
- 后台左边多了一项 **设备同步**。
