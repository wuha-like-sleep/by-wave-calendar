# 转传本地发行包到 Gitee

`.github/workflows/mirror-release-to-gitee.yml` 只下载、校验和上传现成发行文件，不编译应用。手动选择 `main` 和已公开发布的版本标签运行；仅允许本公开仓库使用标准 Ubuntu 运行器，原编译 CI 保持停用。

- 仓库 Secret：`GITEE_RELEASE_TOKEN`，凭据只通过标准输入传给上传程序，不写入日志、Git 或发布文件。
- 标签：`vX.Y.Z`、`desktop-vX.Y.Z`、`android-vX.Y.Z`。对应标签及提交应先推送到两个仓库。
- 所有文件必须具有 SHA-256 清单。服务端归档额外校验项目既有 Ed25519 签名。
- 转传前检查 Gitee 单附件 100 MiB 限制；上传后匿名下载并核对大小和 SHA-256，全部通过才改为正式发行版。
- 超时后重新运行同一标签会先检查已有附件；匹配的附件校验后跳过，拒绝重复或覆盖不一致的文件。各版本独立排队。
- 同一发行版最多并行传输三个不同附件，每份下载校验使用独立临时文件。单次大文件上传最多等待三小时，整个转传任务最多六小时；任一文件失败都不会发布为正式版。

Gitee 某个 DNS 节点无法连接时，可临时设置仓库变量 `GITEE_RESOLVE_IPV4` 为当前 DNS 中可用的公开 IPv4。程序仍请求 `https://gitee.com` 并验证它的 TLS 证书，不转发认证请求、不接受内网地址。网络恢复后删除该变量即可恢复正常 DNS 解析。

## 已公开的 Mac 安装包超过附件限制

不要覆盖已经公开的安装包或改变原 URL 的内容。可在本机对相同的已签名应用使用更大的镜像压缩块，重新签名、公证并验证镜像；确认包内应用与原公证版本逐文件一致。在同一 GitHub 发行版追加：

- `ByWaveCalendar-X.Y.Z-arm64-compact-signed.dmg`
- `SHA256SUMS-compact.txt`，只包含上述镜像的 SHA-256，格式与主校验清单一致。

转传程序仅接受这两个完整的附加文件，随后使用压缩版代替超限的 Apple Silicon 镜像。Gitee 中的 `SHA256SUMS-compact.txt` 校验压缩版；原 `SHA256SUMS.txt` 和 `latest.json` 仍对应 GitHub 原发行包，避免破坏已缓存的更新清单。发行说明应明确两者应用内容相同。

后续本地 Mac 打包默认使用 4 MiB 压缩块，并在公证前及最终输出时检查容量限制。容量仍超限时停止发布，先调整本地打包方案。
