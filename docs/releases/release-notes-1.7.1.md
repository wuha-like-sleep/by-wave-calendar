# 服务端 1.7.1

> 取代 1.7.0。**这一版全是安全修复，建议尽快升。**
> 升级不用改任何配置，数据库迁移随启动自动应用。

---

## 一、四个洞，都已经开着很久了

### 1. 有账号密码就能绕过两步验证

任何人只要有账号密码（撞库、泄露库、钓鱼），打一个接口就能拿到一个**已经算通过两步验证**的完整会话 —— 网页、后台、API 全放行。管理员账号也一样，连「强制管理员启用两步验证」那个开关也拦不住。

网页登录表单那条路一直是对的。问题出在另一条不需要浏览器的路上，两条路的口径不一样。

顺带堵上：停在「请输入验证码」那一页的人，以前就已经能给账号装一个新的 Passkey（之后永远免密登录，**你改密码也清不掉**）、删掉你已有的 Passkey、或者绑一个他自己的外部登录账号。

**三端 App 不受影响** —— 它们用的是另一条接口，那条一直是对的。

### 2. 第三方授权的权限范围从来没生效过

后台那排「只读 / 读写」的勾选框是假的。给一个第三方工具勾「只读日历」，它拿到的令牌实际能建、能改、能删事件，能删掉你整本日历。

更严重的是有两条路能把那个令牌换成完整账号控制权，其中一条换出来的设备凭据**即使你后来撤销了这个应用，它仍然活着**。也就是说「授权一个只读小工具」实际等于「把账号交出去，而且收不回」。

现在按同意页上写给用户看的那几句话严格执行。

> ⚠️ **这会影响你现有的第三方集成。** 以前它们能做任何事。现在「创建、修改、删除你的事件」这句话不包含：日历本身的增删、对外分享链接、预约链接 —— 这些对第三方一律拒绝。如果你有集成因此报错，那正是它以前在做承诺之外的事。

### 3. 后台「关闭第三方 API」这个开关是坏的

你按下去，页面变灰、提示「现存 token 暂停工作」。实际上只关了一半：长效 API 令牌确实停了，而 OAuth 授权出去的令牌**照常读写你的日历**，关着开关还能签发新的。

出事时你会以为已经切断了。现在真的切断，而且「谁什么时候按的」会留审计记录。

### 4. CalDAV 可以被无限次在线猜密码

CalDAV 是全站唯一一处完全不受访问频率限制的登录入口，而在没开两步验证的账号上（多数账号的默认状态），它收的就是你的**账号主密码**。猜中即完整账号沦陷。整个过程服务端不留任何痕迹、不触发账号锁定、后台也看不出正在被打。

另一半更紧迫：**不需要猜中任何密码**就能把整站拖死 —— 每个请求都强制服务器算一次密码哈希，而那是在唯一的主线程上。

现在按「认证失败」限速而不是按请求数限 —— 配置正确的日历客户端稳态下产生 0 次失败，成本为零；手机上攥着旧密码猛打的那种情况只算一次，不会误伤。后台首页新增一块，能看到有没有人在撞。

## 二、后台新增

**设置 → 安全**，两个开关：

| 开关 | 默认 | 什么时候该改 |
|---|---|---|
| Passkey 必须做过用户验证 | 开 | 一般不用动。关掉的话，一把插上就能用、不需要指纹/PIN 的硬件钥匙也等同于通过两步验证。 |
| SSO 登录算作已通过两步验证 | 开 | **你接的外部登录源如果允许用户自己填邮箱，请关掉它** —— 那种情况下，别人在对方那边注册一个你的管理员邮箱就能登进来，本站的两步验证被整条绕过。公司自建、邮箱由 HR 同步的 Keycloak 没这个问题。 |

第一个开关**不会把任何人关在门外**：没做用户验证的 Passkey 不是被拒绝，而是只等于密码 —— 开了两步验证的账号补一次验证码，没开的照常登录。

**运维 → 客户端更新**（新页面）：能看到三端 App 的更新清单现在实际生效的是哪一份，也能自己贴一份覆盖它。一般用不上 —— 默认跟着本站程序走，你升级服务端时清单自动更新。只有你想自己决定推哪一版时才用得到。

## 三、一个你可能会注意到的变化

从这一版起，发版包里会带上三端 App 的更新清单。以前不带，所以走后台「系统更新」升级的服务器拿不到它 —— 后果是**你自己的下载页会一直显示旧版本号和旧下载链接**，而你并不会收到任何报错。

（App 用户受影响较小：安卓和桌面端都有回源上游的兜底。真正受害的是你的下载页。）

## 四、下载页可以从你自己的服务器发安装包了

以前 `/download` 上的每个下载按钮都指向 GitHub —— 也就是说你的用户（包括国内用户）下 100MB+ 的安装包，走的是 GitHub 的线路，慢，而且经常中途失败。

现在的规则是：**这台服务器上真的有这个安装包，就优先给本站链接**，GitHub 作为一行小字的备选留着（本站下不动的人还有退路）。服务器上没有就跟以前一样只给 GitHub。

判断依据是真的去看文件在不在、是不是 0 字节，不是「清单里写了文件名就算有」—— 后者会让用户点出一个 404。

**怎么启用**：把安装包放到程序目录下的这两个文件夹里，文件名和清单里的 `filename` 一致即可：

```
<程序目录>/data/desktop-binaries/    ← DMG / MSI / DEB
<程序目录>/data/android-apks/        ← APK
```

宝塔的文件管理器直接拖进去就行。放完刷新一下下载页，按钮就换成本站的了。三个桌面包加起来约 300MB，注意你的磁盘和出口带宽 —— 每个用户下载都走你的流量。

不想用就什么都别放，行为和以前完全一样。
