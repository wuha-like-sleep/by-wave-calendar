# 服务端 1.9.2 · 桌面端 1.3.2 · Android 0.13.2

## 预约时间与操作体验

开放时间按预约所选日历的时区计算，支持跨日、半小时时差和夏令时。公开预约及取消页面默认按访客设备时区显示，可切换到发起方时区；切换时区保留已选时段与填写的信息，不改变已经约定的时间。时钟回拨时重复出现的时段分别标明时区，避免把两个不同时间当成同一个预约。全天日程按发起方的本地日期阻挡预约，覆盖跨日、多日和夏令时 23/25 小时的日期。

网页和各端预约管理显示排期所属时区。App 日程详情标明显示时区与日程时区，手机切换时区后刷新时间与日期分组；电脑更改系统时区后需要重启桌面 App。预约提交失败保留访客信息并重新加载空闲时段；已有未结束预约的链接需要先暂停或处理预约，避免删除链接后访客无法取消。

双方各自显示自己的时间：同一预约可在发起方显示墨尔本 12:00（夏令时）、访客显示上海 09:00。确认邮件分别按发起方日历时区和访客所选显示时区发送，取消通知保留访客的显示时区；这项偏好不会改变发起方排期、日程时区或真实预约时刻。

直接删除日程或从 Outlook 同步删除时，同步取消关联预约并通知访客。恢复已取消的预约日程会恢复为个人日程，原取消链接不会再次删除恢复后的日程。

## 日历编辑与删除同步

修复西半球时区下日期选择器偏移一天、全天日程显示和复制日期偏移，以及清空描述、地点、会议链接或会议密码后无法保存的问题。

未改动的定时字段保存时保留原始时刻，避免夏令时回拨重复小时、编辑期间设备切换时区或时间精度变化造成预约偏移。

重复事件的单次和后续修改在事务内完成，保留提醒、排除日期和重复结束条件。失效的单次操作会提示刷新，避免误改整个系列；并发删除不同实例时合并排除日期，旧的删除请求不会重新延长已截断的系列。

修复一批重复实例同步时将自身修改误判为外部冲突、逐条等待重试的问题。同步账号独立使用工作槽位，缓慢账号不会占住其他空闲槽位；版本竞争快速重试，服务商限流仍按要求等待。桌面详情窗口持续接收刷新；Android 删除确认后立即移除本地缓存、提醒和已启用的系统日历镜像，并阻止较早的刷新响应把它们重新写回。

外部服务仍受自身轮询和客户端刷新影响，不能保证所有设备即时完成删除。手机的系统日历镜像保持现有方向，未将其改称双向同步。

## 安装与分发

所有安装包在本机或本机 Windows 虚拟机编译。macOS 使用既有 Developer ID 签名及 Apple 公证，Android 使用既有发布证书；Windows 安装器仍未签名。GitHub 编译 CI 保持停用，免费标准 Ubuntu 运行器仅转传已验证文件到 Gitee。

预约时区计算、事务一致性及服务器同步修复需要服务端升级至 1.9.2。桌面端版本代码 29，Android 版本代码 25。本轮不发布新的 iOS 或 Linux 二进制包。
