# 服务端 1.9.1 · 桌面端 1.3.1 · Android 0.13.1

## 更新与缓存

桌面端和 Android 同时比较服务器及公开更新清单，选择有效的最高版本。成功检查缓存六小时，网络失败一分钟后可自动重试；手动检查随时可用。并发检查合并请求，取消不会被误报为已是最新版，缺少完整安装包校验信息的清单不会用于提示升级。

桌面事件缓存改用独立账号目录和原子写入，最多保留 32 个日期窗口，七天过期。新建、编辑、删除和撤销成功后清理该账号的旧快照，避免切换视图后显示旧事件。Android 在一个事务中更新事件和日历缓存，清理缓存与正在进行的刷新互斥；退出账号先撤销账号访问，再完成本机缓存、提醒及日历镜像清理。删除撤销绑定原账号，切换账号后不再沿用旧撤销操作。

## 预约一致性

同一日历的预约请求按事务锁串行校验，提交时重新检查链接状态、账号状态、可用时段、事件冲突和预约时长。修复首尾相接的预约被误判为冲突、缓冲区边缘的冲突漏查、重复或乱序开放时间窗，以及上海午夜后的日期计算。重复事件继续按事件时区展开并扣除已删除的单次实例。

预约取消与关联日程删除在同一个事务提交；失败时一起回滚，重复取消保持幂等，并可修复旧版已取消但日程仍存在的记录。预约新增及取消提交后主动通知日历同步队列。

## 安装与分发

安装包在本机及本机 Windows 虚拟机编译。GitHub 仅使用公开仓库的免费标准 Ubuntu 运行器转传已经发布的文件到 Gitee；转传前后核对大小与 SHA-256，服务端更新包额外验证 Ed25519 签名。原编译 CI 保持停用。

服务端预约修复需要管理员升级至 1.9.1。Windows 安装器仍未签名；macOS 使用既有 Developer ID 签名与 Apple 公证，Android 使用既有发布证书。此轮不发布新的 iOS 或 Linux 二进制包。
