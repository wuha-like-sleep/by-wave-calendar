# Windows 与 macOS 系统日历双向同步

桌面客户端 1.2.0 的「设置 → 系统日历」会在已登录的浏览器中打开配置页。
服务器须更新到包含此功能的版本；入口为 `/app/settings/calendar-sync`。
同步需要用户主动连接账号和选择日历。退出桌面应用不会停止服务器或系统日历的后台同步。

## macOS「日历」

1. 服务器配置可公开访问的 HTTPS `PUBLIC_BASE_URL`，并使用有效证书。
2. 在系统日历设置页创建专用应用密码，复制一次性显示的密码。
3. 下载 CalDAV 账户描述文件，在 macOS「系统设置」中检查并安装。
4. 输入应用密码，打开系统「日历」，选择 ByWave 账户的日历。

描述文件不包含密码。也可手动添加 CalDAV 账户：服务器为设置页显示的地址，
用户名为 ByWave 登录邮箱，密码为刚生成的应用密码。不要使用 SSO 提供方的密码。
通过 CalDAV 同步事件、重复规则和删除；实际刷新频率由 macOS 的账户设置决定。
不再使用时，在系统设置删除账户，并在 ByWave「应用密码」中撤销对应密码。

## Windows 新版及经典版 Outlook

支持两种 Outlook 中的 **Microsoft 365 / Outlook.com 云端日历**。
通过 Microsoft Graph 同步账号中的日历，所以 Outlook 不必一直打开。
本地 PST、仅本机保存的日历、IMAP 账户附带的本地日历以及非 Microsoft 服务不在此接入范围。

### 站长只需配置一次 Microsoft 应用

1. 在 [Microsoft Entra 管理中心](https://entra.microsoft.com/)的「应用注册」中新建 ByWave Calendar。
2. 支持的账户类型选择「任何组织目录中的账户和个人 Microsoft 账户」。
3. 在「身份验证 → 高级设置」开启「允许公共客户端流」。本实现使用设备代码登录，不需要重定向 URI 或客户端密钥。
4. 添加 Microsoft Graph **委托权限** `Calendars.ReadWrite`、`User.Read`、`offline_access`。
   企业租户可能要求管理员同意；请遵循所属组织的权限流程。
5. 复制「应用程序（客户端）ID」，在服务器 `.env` 设置：

   ```dotenv
   MICROSOFT_CALENDAR_CLIENT_ID=你的应用程序UUID
   ```

6. 重启服务，使环境变量生效。容器部署须将变量传入容器；PM2 使用现有部署配置并更新环境。

此 ID 是公开标识，不是密钥。不要在此字段填写客户端密钥。
未配置 ID 时设置页会说明原因，不会显示一个无法完成的连接按钮。
参考：[桌面应用配置](https://learn.microsoft.com/en-us/entra/identity-platform/scenario-desktop-app-configuration)、
[设备代码登录](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)。

### 用户连接

1. 进入「设置 → 系统日历 → Outlook」，开始连接。
2. 在 Microsoft 官方页面输入设备代码，核对应用、账号与授权范围，再返回 ByWave 完成连接。
3. 选择一个自己拥有的 ByWave 日历和一个可编辑的 Outlook 日历。
   建议用「新建 Outlook 日历」创建专用日历，先用少量日程确认效果。
4. 添加同步关系。首次连接会合并两边的日程，不按标题猜测或自动合并同名事件。
5. 页面显示上次同步、错误及冲突。可手动同步、暂停或恢复。

### 同步范围与冲突

- 后台约每分钟检查，Microsoft 限流或临时错误时自动延迟重试；大量日程分批处理。
- 首次发现的日程范围为过去 90 天至未来 365 天。已建立映射的日程即使移出窗口仍被跟踪，移出窗口不等于删除。
- 同步标题、说明、地点、起止时间及全天状态。重复日程在另一侧展开为单独的发生项；不创建另一侧的重复系列规则。
- 不复制参会者、邀请、提醒和附件；原有事件的额外字段会保留。不要把此功能当成会议邀请管理工具。
- 一侧删除而另一侧未改动时，会同步删除。双方都修改，或一侧删除同时另一侧修改时，保留冲突，由用户选择采用哪一侧。
- 冲突解决前会再次核对版本，避免覆盖用户刚做的新改动。
- 日历失去访问权限、分页失败、重复规则无法完整展开时，停止本轮同步，不会把失败当作空日历传播删除。
- 每个本地日历和每个远端日历只能加入一组关系；每用户最多 10 组。断开连接会删除凭据和映射，保留两边现存日程；重新连接会重新合并，因此建议保持现有关系并重新授权同一 Microsoft 账号。

### 凭据、备份与运维

刷新令牌与临时设备代码按用户加密保存，密钥由服务器 `SESSION_SECRET` 派生。
妥善保留该配置与数据库备份。更换密钥后需重新授权，映射仍保留。
临时设备代码不进入备份；恢复备份会清除执行租约并暂停所有同步关系。
管理员或用户应先确认两边日历内容，再逐组恢复，避免旧备份覆盖外部新内容。

自动化测试覆盖双向增删改、并发冲突、夏令时、分页故障、权限撤销、断点恢复、
授权会话绑定、加密凭据、备份恢复暂停和访问控制。实际 Microsoft 登录与系统日历接入仍需要有效账户及站点配置。
